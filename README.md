# AI Plugin Manager для Pi

Команда `/plugin` добавляет Git-источники плагинов, хранит общий клон каждой
поставки вне проектов и даёт каждому проекту свой набор плагинов.
Репозиторий содержит только менеджер, не сами плагины.

Установите менеджер один раз **без `-l`**, чтобы `/plugin` появился во всех проектах:

```bash
pi install git:github.com/GravRnD/ai-plugin-manager
```

Нужны Pi, Git и Python 3; отдельную команду `pi-plugins` в `PATH` ставить не нужно.
В уже открытом Pi выполните `/reload`.
Обновить сам менеджер: `pi update git:github.com/GravRnD/ai-plugin-manager`.
Для разработки из локального клона: `pi install "$PWD"` из его корня.

1. В нужном проекте откройте `/plugin` → **Скачать и подключить**. Введите адрес
   репозитория, например `git@github.com:team/tools.git`. Менеджер сразу скачает
   поставку и предложит подключить пакет; если их несколько, выберите нужный.
2. При первом подключении в bash или zsh подтвердите настройку и откройте новый
   терминал. Дальше запускайте обычный `pi`. При смене личного набора запустите
   Pi заново (`pi --continue` продолжит последнюю сессию).

Личный выбор хранится вне репозитория: он не меняет `.pi/settings.json`
и не отображается в `pi list`.

Выберите установленный плагин, чтобы увидеть **Обновить** и **Удалить**.
Обновление подтягивает его Git-источник целиком; удаление отключает плагин
в выбранном проекте и не стирает скачанные файлы.

Личный список применяется к Git-worktree, включая его подкаталоги.
У разных worktree списки отдельные. Лаунчер читает список при старте процесса:
`/reload` обновляет код уже загруженных пакетов, но не меняет состав списка.
Записи, ранее добавленные в `.pi/settings.json`, не мигрируют автоматически.

После `/plugin ` появятся подсказки. Действия можно вызывать напрямую:

| Команда | Что делает |
| --- | --- |
| `/plugin add [адрес] [имя]` | Скачать Git-источник и предложить подключить пакет. Без адреса открывает диалог |
| `/plugin local` или `/plugin -l` | Выбрать личные плагины проекта, не меняя его файлы (`personal` также работает) |
| `/plugin setup-local` | Подключить личный список к обычному `pi`, если пропустили настройку |
| `/plugin list` | Управлять записями в `.pi/settings.json` проекта |
| `/plugin update` | Обновить Git-источник |
| `/plugin commands` | Показать команды пакетов в этой сессии. Выбор подставляет команду в строку ввода, не запуская её |
| `/plugin help` | Показать эту справку |

Например, `/plugin add git@host:team/tools.git` сохранит источник под именем
`tools`. Если это имя занято, менеджер подберёт `tools-2` и т. д.
При желании имя можно задать явно: `/plugin add git@host:team/tools.git team-tools`.

Можно добавить репозиторий с одним Pi-пакетом в корне (`package.json` с
секцией `pi`) или коллекцию с пакетами в отдельных каталогах. Если есть
оба варианта, меню показывает отдельные пакеты, чтобы не дублировать их.
Пример коллекции:

```text
team-tools/
├── comments/package.json
└── tasks/package.json
```
Для приватных репозиториев настройте доступ Git заранее, например ключ в `ssh-agent`
и проверенный ключ хоста. Добавляйте только источники, которым доверяете:
подключённые расширения выполняют код с правами Pi.

Адреса хранятся в `~/.config/pi-plugins/sources/`, новые клоны — в
`~/.local/share/pi-plugins/git/<репозиторий>--<хеш>/` (поддерживаются
`XDG_CONFIG_HOME` и `XDG_DATA_HOME`). Ранее скачанные клоны остаются на месте.
Личный выбор хранится в `~/.config/pi-plugins/projects/`. `setup-local` добавляет
в `.bashrc` или `.zshrc` отмеченный блок `ai-plugin-manager: local Pi`, который
ставит обёртку перед Pi в `PATH`. Обёртка передаёт выбранные пакеты через `-e`,
не меняет бинарник Pi, настройки проекта или доверие. Чтобы отменить настройку,
удалите отмеченный блок и откройте новый терминал. Для других оболочек
`/plugin launcher` по-прежнему создаёт отдельную команду `pi-with-plugins`.
